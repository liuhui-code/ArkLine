## 第一阶段交付

### 1. 外部文件变更与安全保存

- 文件监听事件进入打开文档：干净缓冲区自动重载，脏缓冲区保留用户内容并记录磁盘冲突。
- 保存请求携带打开时的原始内容；磁盘已变化时拒绝覆盖，编辑器保持脏状态并显示失败原因。
- 单文件保存使用同目录临时文件、同步和替换，避免直接截断目标文件。

### 2. 精确 Find Usages 与真实 SDK 边界

- 引用查找使用 TypeScript 符号身份跨文件解析，不再把同名文本当作语义引用。
- 语义模式返回空结果时不降级到词法匹配，宁可明确无结果，也不制造错误引用。
- 黄金语料新增同名干扰项；真实 HarmonyOS SDK 冒烟测试验证系统类型定义与成员补全。

### 3. 安全 Rename Symbol

- `F2` 打开独立 Rename Symbol 对话框；`Alt+Enter` 保留代码动作与 Rename File，避免概念混用。
- Worker 使用语言服务的 rename info/locations，只产出预览，不直接写盘。
- 每个编辑携带期望内容版本；应用前统一预检，任一文件变化即拒绝整次编辑。
- Rename 的纯文本工作区编辑生成一次性逆向计划；撤销同样校验应用后的版本，拒绝覆盖后续修改。

### 4. 纯文本多文件事务日志

- 在写入第一个目标文件前，先把所有原内容、新内容和 `prepared` 状态持久化到 workspace-local journal。
- 每个目标文件通过同目录临时文件原子替换；全部完成后原子发布 `committed` 状态，再清理 journal。
- 重新打开工作区时先恢复事务再扫描：`prepared` 回滚到全旧，`committed` 前滚到全新。
- 恢复先读取并校验所有文件；出现既非旧版本也非新版本的第三版本时，拒绝覆盖任何文件并保留恢复证据。
- 真实测试子进程覆盖 journal 目录创建后、空 journal 发布后、首文件替换后和 committed 清理前四个退出点。

### 5. 语义可用性契约

- Find Usages 的公共结果不再是裸数组，而是 `ready`、`partial`、`unavailable` 加结果与解释；只有 `ready + 空结果` 才能显示“无引用”。
- 索引未就绪且没有可用结果时，Usages 面板显示 `unavailable`；已有但不完整的结果显示 `partial`，状态栏不会再宣称结果完整。
- Worker 缺少查询位置时明确失败；Rust 不再用空数组吞掉 Worker 错误，并依据 Worker 的 `typeStatus` 发布可用性。
- Rename Symbol 使用相同 envelope；`partial` 或 `unavailable` 均停留在重命名对话框并阻止预览/应用，只有 `ready` 才能进入工作区编辑事务。

### 6. 文件与目录操作事务

- 文件 journal 升级为二进制安全的 v3 blob：创建、删除、覆盖式重命名与文本编辑共享 before/after 状态机；v1/v2 文本 journal 仍可恢复。
- 目录创建记录事务实际创建的每一级祖先；prepared 恢复只删除这些空目录，发现外部内容即整体拒绝且不先做部分回滚。
- 目录删除先把完整目录树原子移动到事务备份；目录重命名保存被覆盖目标，并在 prepared 恢复时逆向移动源与目标。
- 目录重命名 journal 保存确定性树指纹；崩溃后若目标出现第三版本，恢复在任何移动前拒绝覆盖并保留 journal 证据。
- 混合文件与目录操作当前没有单一提交点，因此预览和应用均 fail-closed；所有未知事务组合也不再落入直接 `fs` 写入路径。
- 同一计划中的结构操作不得命中祖先/后代路径，避免前一操作破坏后一操作的恢复前置条件。

### 7. 诊断快照与 Quick Fix 安全预览

- 编辑器内联诊断和 Problems Controller 均绑定请求时的路径与内容快照；异步返回时快照已变化则丢弃旧结果。
- 生产编辑器中的内联 Quick Fix 不再直接修改缓冲区，而是生成单文件文本 Workspace Edit 并进入统一预览。
- Quick Fix 计划携带与 Rust 后端一致的 FNV-1a `expectedContentVersion`；预览和应用均复用既有冲突检查、事务应用与 Undo 链路。
- 未保存缓冲区与磁盘版本不同时当前安全报告冲突，不会为了应用 Quick Fix 覆盖任一版本；开放缓冲区事务留待后续独立契约。

## 自我质询后的边界

以下项目没有被包装成“已经成熟”：

1. 文件操作与目录操作分别具备崩溃事务；跨两类操作的单个计划尚无统一提交点，当前在预览和应用阶段明确拒绝，而不是降级为非原子写入。
2. 单次 Undo 只为本阶段的纯文本 Rename 计划生成，不代表文件创建、删除、移动和目录操作均可撤销。
3. 真实 SDK 证据来自本机已安装的 HarmonyOS SDK；Windows 打包应用仍应在 Windows runner 上执行真实 packaged smoke。
4. `partial` Rename 当前采取保守策略：即使携带编辑计划也禁止预览和应用；未来若允许部分重命名，必须设计独立命令和显式风险确认，不能复用安全 Rename。
